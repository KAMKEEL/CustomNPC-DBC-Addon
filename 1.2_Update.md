# ⚡ DBC Addon 1.2

---

The **1.2 Update** is the biggest DBC Addon release yet! Custom forms can now **stack** with vanilla DBC forms, NPCs can unleash **21 unique ki-based abilities** with full DBC damage integration, **10 toggleable DBC moves** bring core combat techniques to the ability system, and the entire **Overlay system** has been rebuilt from the ground up with scripting support. On top of that, a brand new **DBC Conditions** system adds 11 condition types for ability logic, and **Custom Skills** let you create entirely new learnable skills!

---

## Form Stacking 🔄

Custom forms can now **stack with vanilla DBC transformations** and with other custom forms, enabling complex multi-layered transformation chains!

### Vanilla Form Stacking

Each custom form can be configured to stack with any combination of vanilla DBC forms:

- **Kaioken** - Stack with Kaioken at configurable levels and multipliers
- **Ultra Instinct** - Stack with UI and set a custom multiplier
- **God of Destruction** - Stack with GoD form
- **Mystic / Potential Unleashed** - Stack with Old Kai Unlock
- **Legendary** - Override the default Legendary multiplier when stacking
- **Divine** - Override the default Divine multiplier when stacking
- **Majin** - Override the default Majin multiplier when stacking

### Custom Form Stacking

Custom forms can also stack with **other custom forms** using the Custom Stackable system. Each form supports up to **4 custom stacking pairs**, linking a source form to a target form for complex multi-form transformation chains.

> Circular dependencies, duplicate source forms, and parent/child conflicts are automatically prevented.

## Form Mastery - Heat & Pain 🔥

Custom forms now support a **full mastery system** with heat and pain mechanics that scale with mastery level.

### Heat

Heat builds up while a form is active. Configure how long it takes to reach maximum heat, and set multipliers that decrease as mastery increases -- rewarding players who train their forms.

- **Max Heat** - Time in seconds to reach full heat
- **Heat Multiplier** - Base multiplier, per-level reduction, and minimum cap
- Forms can be configured to generate no heat at max mastery level

### Pain

When a player descends from a form with enough accumulated heat, they enter a **pain state** that temporarily debuffs them. Pain duration and intensity scale with mastery.

- **Pain Time** - Duration in minutes
- **Pain Threshold** - Minimum heat percentage (0-100%) before pain activates on manual descend
- **Pain Multiplier** - Base multiplier with per-level reduction, so mastered forms cause less pain

## DBC Damage on Abilities 🎯

Abilities now support **full DBC damage calculations** instead of vanilla Minecraft damage. A damage handler intercepts ability hits and routes them through the DBC combat system, applying all relevant modifiers, resistances, and combat stats.

### Per-Ability DBC Stats

Every ability has its own configurable DBC combat stats:

- **Friendly Fist** - Prevent lethal damage for a configurable duration (1-60 seconds)
- **Ignore Dex** - Bypass dexterity-based dodge rolls
- **Ignore Block** - Bypass block damage reduction
- **Ignore Endurance** - Bypass endurance-based resistance
- **Ignore Ki Protection** - Bypass ki protection shields
- **Ignore Form Reduction** - Bypass form-based damage reduction
- **Defense Penetration** - 0-100% armor penetration

### DBC Damage Integration

DBC damage routing extends across the entire ability system:

- **Energy Projectiles** - All orbs, beams, lasers, and discs deal DBC-calculated damage
- **Barriers** - Barrier HP scales with DBC stats; ki attacks properly collide with barriers and can be redirected back at attackers
- **Healing** - Healing abilities scale with DBC health values
- **Counter / Dodge / Guard** - Defensive abilities properly interact with DBC damage calculations
- **AOE / Zones** - Panel, sweeper, and zone abilities route through DBC damage

### GUI Integration

A dedicated **DBC Stats tab** appears in the ability editor for any ability that deals damage. All DBC stats are configured per-ability and saved in the ability's custom data. The stats system can be globally enabled or disabled, and defaults are configurable per-NPC.

> DBC damage stats are also accessible through the scripting API via `getAbilityDBCStats()`.

## DBC Conditions 🔍

A brand new **DBC Conditions** system adds **11 condition types** for controlling when abilities can be used, all registered under the `npcdbc` namespace with a **"DBC Addon"** group label.

### Threshold Conditions

- **Ki Threshold** - Check player's current Ki against max Ki (percentage or flat value)
- **Stamina Threshold** - Check player's current Stamina against max Stamina (percentage or flat value)
- **Stat** - Check any of the six DBC stats (STR, DEX, CON, WIL, MND, SPI) against a flat value

### Identity Conditions

- **Race** - Require a specific DBC race
- **Class** - Require a specific DBC class (Martial Artist, Spiritualist, Ki Swordsman)
- **Level** - Check the player's DBC level with comparison operators (equal, greater, less, etc.)

### State Conditions

- **Form** - Require a specific form to be active and/or unlocked (supports both DBC and custom forms, works for players and NPCs)
- **Fused** - Check if the player is currently fused
- **Locked On** - Check if the player has an active lock-on target
- **DBC Effect** - Check for a specific DBC status effect
- **Skill** - Check both DBC skills and custom skills against a level threshold (0-10)

> All conditions support checking the **Caster**, the **Target**, or **Both**, and appear in the ability condition GUI with proper DBC-styled selection interfaces.

## Overlay System Overhaul 🎨

The entire overlay rendering system has been **completely rebuilt** with a new architecture for maximum flexibility. Overlays now cover both face and body rendering in a unified system.

### Overlay Chains

Overlays are organized into **Overlay Chains** -- named groups of overlays that render together with shared conditions.

- **Conditional Rendering** - Chains activate based on form state, race, gender, or custom predicates
- **Face Part Control** - Chains can disable specific face parts (eyebrows, eyes, nose, mouth)
- **Named Organization** - Chains are named for easy identification and management
- **Enable/Disable** - Individual chains can be toggled independently

### Overlay Types

Overlays can target **specific body parts** for precise rendering:

**Face Parts:** Face, Eyebrows, Eye Whites, Left Eye, Right Eye, Nose, Mouth
**Body Parts:** Chest, Arms, Left Arm, Right Arm, Left Leg, Right Leg, Legs, or ALL

### Dynamic Color Sources

Overlays can pull colors dynamically from the character:

- **Custom Color** - A user-defined color value
- **Eye Color** - The character's current eye color
- **Hair Color** - The character's current hair color
- **Fur Color** - The character's fur color (for SSJ4, Oozaru, etc.)
- **Body Colors** (CM, C1, C2, C3) - Arcosian body colors for form-specific rendering
- **Glow** - Emissive rendering that ignores lightmap for glowing effects

### Built-in DBC Overlays

Pre-configured overlay chains ship with the addon, covering the most common transformation visuals:

- **Pupils** - Race-specific pupil rendering for all races, genders, and body types (including HD/SD texture support)
- **SSJ3 Face** - Custom face with hidden eyebrows and unique eye whites
- **SSJ4 Face** - Fur-colored eyebrows with custom eye rendering and glow effects (includes Daima variant)
- **SSJ4 Fur** - Full body fur texture overlay with multiple fur types (including Legend variant)
- **Oozaru Fur** - Great Ape fur overlay for all NPC races
- **Savior from Heaven** - Fur and glowing effect overlays
- **Black Frieza** - Body textures for all three Arcosian body types with matching eyebrows
- **Namekian Overlays** - Race-specific Namekian body textures
- **Berserk Eyes** - Dynamic berserk eye rendering baked into the overlay pipeline

### Overlay GUI

The overlay editor GUI received a **major renovation** with improved layout, scrolling, type selection, overlay chain management, and an integrated Janino script editor. Forms can now disable specific overlay types through `FormDisplay`.

## Overlay Scripts 📜

A brand new scripting system for overlays using **Janino** (Java-like) compiled scripts.

- **Dynamic Textures** - `getTexture(ctx)` returns texture paths based on entity state. Supports regex-based texture path replacement for easy context-driven swaps
- **Dynamic Colors** - `getColor(ctx)` returns colors based on entity state
- **Rich Context** - Scripts have access to the full `OverlayContext`: entity data, race, gender, age, body type, current form, eye/hair/fur colors, mouth, nose, and more
- **Per-Overlay Scripts** - Each overlay can have its own script for independent logic
- **Custom Renderers** - Overlays can define custom render functions through scripts

> Overlay scripts compile at edit time and execute every render frame for real-time dynamic overlays.

## Script Editor Hook Integration 🔗

All existing DBC Addon scripting hooks are now **registered into the CNPC+ Script Editor** through the new `ScriptHookController`, so they appear in the editor's hook dropdown with proper parameter names and autocomplete.

## Easing Function API 📈

A new API for smooth interpolation curves, used internally for energy projectile size interpolation and available to scripters.

- **Normalized Input** - Primary `ease(double t)` method takes 0.0-1.0 progress values
- **Time-Based** - Convenience overloads for start time, total duration, and current time
- **Baking** - Easing functions can bake themselves to piecewise linear approximations for performance
- **Built-in Types** - Constant, Linear, and LinearPiecewise implementations included
